# Soycatory — rules for working in this repository

This repository is Soycatory, the Soya Software Factory, and its front page. The product is the factory, not a studio: it makes small apps, and it is never described as a film or movie company. The front page lists the apps (small web apps) for day-to-day people who are not technical. The factory makes new ones.

1. **Factory runs follow `factory/FACTORY.md` exactly.** Read it first. A run opens a pull request and never merges it.
2. `factory/decision-maker/` is a Node tool, not an app: no dependencies, no `package.json`. Check it with `node --test factory/decision-maker/server.test.mjs`.
3. Apps made here live in `apps/YYYY-MM-DD-slug/`, each self-contained, with its own storage-key and cache-name prefix.

4. Vanilla HTML, CSS and JavaScript. No framework, no build step, no backend, no cookies, no analytics, no ads, no tracking.
5. **One narrow exception, asked for by Ran on 2026-11-20:** `videos.html` may count how far each video is watched (play, each quarter, finish, pause, where the viewer leaves) and take comments tied to a moment in the video. It sends only if `waitlist.js` has a receiver address; it uses no cookies and stores nothing in the browser (a random number made for one visit lives in memory only); it sends nothing to anyone whose browser sends Do Not Track or Global Privacy Control; and the page tells viewers what is counted. **Extended by Ran on 2026-11-21:** `newsletter.html` may count, under exactly the same rules, which items are opened with "Read more", which sources are opened, Yes/No answers, and how far down the page a reader gets, and take topic requests. **Extended by Ran on 2026-11-21 (Supabase, grown-up pages only):** `shared/soya-metrics.js` counts page views, taps that open an app, installs and page errors on the front page, `support.html`, `cv/`, `newsletter.html`, `videos.html`, `one-pager.html`, `accessibility.html` and the grown-up apps (Market Radar, Kafka Check, Cat Factory, Idea Room, Plain Steps, Say It Kindly, Read It Simply). Same rules: no cookies, nothing stored, a random visit number in memory only, nothing sent under Do Not Track or Global Privacy Control, and a one-line notice in the footer. Records go to Supabase `sc_events` with the publishable key (insert only). The kids' apps (Soya News, Animal Facts, Soya's Games) never load it and count nothing. Nothing else on the site is measured.
6. The waiting-list and request forms on a one-pager send only what the person types, only with the receiver address set, and a waiting-list email needs a ticked consent box.
7. Soya News (`apps/2026-11-21-soya-news/`) counts nothing in the background. Its topic box, paw ratings and bug reports send only what the reader chooses, with no name or email, and only with the receiver address set. Its "Meet my human" section, in Soya's voice, uses Ran's photo (`assets/ran.jpg`, from his company's management page, at his request). Its treat box ("Buy Soya a tuna can", marked for grown-ups) only links out to the donation page set in `donate.js`; no payment or card details pass through the app, and an empty link means the box says it opens soon. Since 2026-11-21 the link is Ran's Bit payment link (a public link with a token, no phone number), kept in `treats.js` for the whole site and in `donate.js` for Soya News; `support.html` is Soya's treat page with the Bit button, its QR code (`assets/treats-bit-qr.svg`) and free ways to help; it counts only page views, under item 5. Supporters' names are never published without asking.
8. `cv/` is Ran's adaptive CV (asked for on 2026-11-21): the reader picks recruiter, tech leader, client or small cat, and the same true story is told their way, in English and Hebrew. Clients and past employers in banking are described, never named. It has six position versions (`?role=principal|data-architect|genai|data-eng-lead|ai-engineer|solutions`), each with its own title, opening, skill order and highlight, a share link and Save as PDF (the browser's print); every version uses the same facts. It stores only the language, the last reader type and the last position, and sends nothing; there is no phone number on it.
9. The list of apps is `apps.js`, newest first. Adding an app is one entry there, with English and Hebrew text.
10. Interface strings live in `I18N` in `app.js`, in English and Hebrew. Hebrew is right-to-left.
11. Only the language choice is stored: `localStorage` key `soycatory-lang`.
12. One filled button on the page (open the newest app). Tap targets at least 48px. No looping motion, with one exception Ran asked for on 2026-11-21: live Soya in Soya News (`soya-live.js`, and the three.js stage in `soya-3d.js` with its library stored in `vendor/`) may walk, blink, wag, smile, orbit, throw confetti and move his mouth while reading aloud; he sits still for anyone whose device asks for reduced motion, and readers can switch him to Calm. Since 2026-11-21 the same Soya and the mouse also live on `support.html` through `shared/soya-buddy.js` (blink, smile, tail wag, a flap when tapped, a talking mouth, a party hat after a treat), still for reduced motion or the menu's Stop movement. Plain words, no jargon.
13. **Writing rule from Ran (2026-11-21), for every bot and run:** never use bullet points, in emails, reports, pull requests, posts, docs or app text. Use numbered lists (1. 2. 3.) or plain sentences. In HTML use `<ol>`, never `<ul>`.
14. Same colour tokens as the apps; see `styles.css`.
15. **Accessibility (asked for by Ran on 2026-11-21):** every main page loads `a11y.js`, the accessibility menu (theme, text size, contrast, readable font, underlined links, stop movement, spacing, skip link), and links the statement at `accessibility.html`. Pages with both themes say so with `<html data-themes="light dark">` and define the other theme's tokens; the front page has a dark theme and the CV a light one, both following the device by default. Menu choices are stored on the device only (`soya-a11y`). New pages and apps add the menu too, and the statement is kept true.
16. Before every push: scan for secrets and for real customer or bank names.
17. Merge to `main` only through an approved pull request. Do not force-push. Only Ran creates tags and releases.
18. **Soya's mouse (asked for by Ran on 2026-11-21):** every app and main page loads `shared/soya-mouse.js`, the mouse on the screen edge with the annabelle-games choices (something is broken, I have an idea, please fix this), a report number, and offline saving. It sends only when the person presses Send: the kind, the words typed, the app, page, version, language, screen size and browser name, never a name, email, picture or recording. Reports go to Supabase `sc_requests` (after-demo-day) with the publishable key, which can only add rows; a daily task emails new ones to Ran. Soya News keeps its own mouse and sends through the same module. New apps add the script too.
